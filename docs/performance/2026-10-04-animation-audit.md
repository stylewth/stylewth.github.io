# 动画检查与优化记录

日期：2026-10-04。检查对象为本地工作区的生产构建，包含任务开始前已有的场景和素材调整。

首页的兔子穿越动画原先通过更新 `left` 移动多个叠加图层，滚动时会重复布局。现在由轨道的 `transform` 承担位移，兔子的尺寸、折射偏移、玻璃裁剪和滚动进度公式保持原有关系。

控制器缓存兔子元素，通过 `IntersectionObserver` 观察固定场景。场景离屏或文档隐藏时移除滚动、尺寸监听并取消待执行帧；恢复显示时读取当前位置。系统的 `prefers-reduced-motion` 设置发生变化时立即切换静态构图，组件卸载时释放观察器和监听器。

## 实测结果

在本机无头 Chrome 中，以 1440 × 1000、DPR 1 运行同一生产页面。每次用 120 个动画帧完成一次正向及反向滚动，通过 Chrome DevTools Protocol 的 `Performance.getMetrics` 读取布局计数。场景离屏后另外派发 12 次滚动事件，记录位置读取次数。

| 检查 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 往返滚动新增布局次数 | 117 | 0 |
| 离屏后的 12 次滚动触发位置读取 | 12 | 0 |
| 动态开启减少动态效果后显示静态构图 | 否 | 是 |
| 动态开启减少动态效果后继续读取位置 | 是 | 否 |

原始测量和响应式结果保存在同目录的 `2026-10-04-animation-audit.json`。帧间隔受刷新率和机器负载影响，不据此宣称所有设备的帧率提升比例。

## 视觉、交互与内存验证

- 在 1440、1024、768、390、320 像素宽度下检查 5%、30%、55%、80% 及反向返回 30% 的滚动位置。进度误差小于 0.2 个百分点，没有水平溢出，返回时的兔子位置一致。
- 将新轨道与原 `left` 定位方式在同一页面逐层比较，最大位置差异约 0.013 CSS 像素，来自浏览器的子像素取整。
- 检查运行中开启、关闭减少动态效果，以及禁用 JavaScript 时的静态构图。后台隐藏、恢复及待执行帧取消另有控制器回归测试覆盖。
- 各宽度重复卸载、挂载首页组件 30 次并强制垃圾回收后，监听器数量不变，DOM 节点没有增长。
- 收藏页检查弹窗打开、Escape 关闭及分类切换。预热两组封面后，在同一分类内重复打开、关闭 15 次，节点数为 433 → 433，监听器数为 53 → 53。另一次独立检查中，连续 15、30 次操作后计数也保持稳定。
- 收藏页现有动画未发现需要修改的持续内存增长，保留其实现。本次内存检查覆盖 DOM 和事件监听器保留情况，不等同于 GPU 显存测量，也不宣称整体内存占用下降。
