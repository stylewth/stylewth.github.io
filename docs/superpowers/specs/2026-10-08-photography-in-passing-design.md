# 途中 · In Passing
## 24 张精选摄影作品集设计

日期：2026-10-08  
网站：Tenghao Wang 的现有 Astro 个人网站  
范围：用户已确定只用 24 张，轻量化、简约艺术风。  
交付状态：视觉设计与接入规格，尚未修改或发布网站。

## 设计结论

设计成一间安静的线上摄影展。白底、黑灰文字、完整画幅；小标题和轻量的专题文字目录为照片让出空间。专栏名为「途中 · In Passing」，一级导航 Photos，目标路径 /photos/。

仅使用现有选片名单中的 24 张。没有额外作品索引、搜索框、原类别筛选、数量标签和大段开场说明。全部照片默认同页浏览，专题入口提供更聚焦的观看范围。点击照片可放大查看。

艺术感来自作品尺寸、横竖画幅与间距，不依赖持续动画。沿用现有网站的 Newsreader 与 DM Sans 自托管字体；中文用系统中文字体回退。

## 桌面 UI

以 1440 × 1000 为设计检查画布。现有网站页眉保持约 72px 高，Tenghao Wang 在左，Home / Work / Updates / Elsewhere / Photos 在右。Photos 只用细下划线指示当前栏目。

内容最大宽度 1280px，桌面外边距约 64px，页眉后留白 48–56px。主体分为左侧约 160px 文字目录与右侧照片区，中间间距 48–64px。

左侧：
- 「途中」28px，下一行 In Passing 14px。
- 间隔 36px 后是「全部」与四个专题，字号 13–14px、行高 28–32px。
- 活动项使用下划线与字重；普通文字链接不加按钮底色。
- 桌面目录可 sticky，停在页眉下方；页面保持正常纵向滚动。

右侧：
- 首张《晨光中的火山》以原始 4981:2802 比例显示，宽约 1000px，图片下方只有小字号作品名。
- 首屏展示完整照片及标题。较矮屏幕限制首图高度、等比缩小宽度并居中，不裁切照片。
- 首张已经计入 24 张；后续从《来时路》开始，没有重复封面。
- 首组双图：《来时路》竖幅约 300px 宽，《白崖与灯塔》横幅约 560px 宽，横幅下移约 60px。各自按原画幅呈现，标题在照片下方。
- 后续交替使用宽幅单图、宽窄双图、居中竖幅。每组最多两张，不能连续复用三组相同的左右排列。
- 作品间距 40–64px，组间留白 80–120px。空白应服务图片大小和观看节奏，而不是把文字或照片推离首屏。

作品名常态可见，14px、灰色。照片可点击，不以悬停才显示名称。鼠标悬停只给轻微的链接反馈，不改变画幅、不缩放作品、不遮盖图像。没有卡片边框、阴影、浮动标签和评分。

## 手机 UI

检查画布 390 × 844，左右边距 20px。页眉保留名字与 Menu；Menu 中可访问原五个网站入口，不把整排导航缩成难读小字。

标题「途中」26–28px，In Passing 13–14px。专题目录合为「全部作品」选择菜单，打开后是全部与四个专题。触摸区域至少 44px。

所有作品单列、全宽、保留原画幅。火山全图下方显示标题，48px 留白后进入《来时路》，再进入《白崖与灯塔》。竖幅可以自然延长页面，不能强裁成方形或横幅。主页面和弹层都不产生横向溢出。

平板从左右目录布局过渡为顶部文字目录；图片编排是否双列由可用宽度决定，低于 768px 使用单列。

## 单图观看器

照片点击后打开一个原生 dialog，背景沿用白色。等比缩放作品以在可用区域完整显示；作品名与位置在图片外侧，例如「来时路 · 02 / 24」。位置随当前专题结果变化。

提供关闭、上一张、下一张。桌面可用 Escape 与左右方向键；手机提供常态可见、至少 44px 的前后按钮。可补充轻扫，但不依赖手势。关闭后焦点回到原作品，原滚动位置不变。首尾作品不循环，不可用按钮明确显示。

打开时才加载大图；用画廊图作为即时预览，保留容器尺寸。加载失败提供「图片加载失败」与「重试」。没有自动播放、持续轮播或强制全屏。

只保留本地浏览所需交互；本次不实现搜索、分享面板、下载工具、EXIF 面板、图片服务或用户账户。无 JavaScript 时主页面可直接浏览全部作品，图片链接可打开对应网页大图。

## 轻量化接入

沿用 Astro 静态站和已有字体，不新增 React、动画库、轮播库或第三方图片服务。建议仅增加 /photos/ 页面、摄影清单、一个画廊组件与少量浏览器交互。主页只增加 Photos 导航；Elsewhere 页面可增加一个短的摄影入口。

每条照片记录包含：稳定 id、作品名、原类别、专题、顺序、显示宽高、网页图片路径、描述真实画面内容的 alt。稳定 id 建立后不随展示顺序改变。网页公开清单不携带 D 盘绝对路径、SHA256 或评审分数。

从原图创建独立网页副本，应用 EXIF 方向后按显示宽度生成 WebP 与 JPEG 回退；优先只使用已有图片处理能力，不为了 AVIF 或其他格式新增长依赖链。建议尺寸 640/1000/1600px，观看器按需加载最长边约 2400px 的版本，最终根据实际清晰度调整。

首张封面优先加载，后续照片 lazy load、async decode；用真实 width/height 预留空间。图库不预加载所有大图。观看器仅在打开后加载当前作品的大图，不预取全部 24 张。用浏览器原生缓存复用画廊副本。

页面交互 JavaScript 目标压缩后不超过约 8KB，首屏摄影图片目标约 200–400KB，手机首屏约 100–200KB，24 张画廊的副本目标约 4–7MB。以上是待实际转换和测量的预算，不是已完成的性能结果；视觉质量优先于强行压缩到数字。

原始照片不改动。网页副本处理方向、色彩配置与必要元数据后，要与原图目视比较，保留内容、颜色和长宽比。

2. 无 87 张索引、无搜索或数量标签，页面不存在未使用的图片资源。

4. 检查 390 × 844、768 × 1024、1440 × 1000 与较矮桌面屏幕，标题、按钮和照片正常。
5. 点击、触摸、键盘都能打开和关闭观看器；焦点和滚动位置恢复正确。
6. 关闭 JavaScript 后仍可浏览照片并打开单张图片。
7. 加载失败与减少动画模式有明确行为；没有一次下载全部原图或大图。
8. 本地完成 npm run build，并用浏览器检查实际请求体积与原图色彩一致性。
